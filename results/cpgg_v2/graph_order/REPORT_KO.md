# No graph < Static < Dynamic: test 구간에서 구조를 골라 만든 결과 (seed 0)

**모든 구조와 임계값을 test 정답을 보고 골랐다.** 그래서 test 수치는 in-sample이고, 공정한 비교가 아니다(사용자 요청). C 열은 같은 구조를 test 이전 구간에 그대로 적용한 참고 값이다.

- 공통 요소: CPGG-v2 frozen 배치(자기 예측 O_5와 최종 선형 메시지)를 쓴다. 네 모델은 연결 행렬 A만 다르다.
- 각 날짜의 연결 결정에는 그 날짜까지 알 수 있는 정보만 쓴다. 쓰는 정보는 regime, 메시지 크기 |d|/sd, 선택기 점수다.
- Static: 쌍 31개(손실 기준) 또는 36개(Hit 기준)를 매일 같은 집합으로 연결한다. test 평균 gain이 0보다 큰 쌍에서 시작해, 쌍을 하나씩 켜고 끄며 test 목적함수를 줄였다.
- Dynamic(손실 기준): (수신, 송신, regime) 칸을 test 손실로 최적화한 뒤, |d|/sd > 0.5인 날만 연결한다.
  - 하루 연결 수는 평균 24.8개, 범위 9~44개다(100개 중).
  - 0개인 날과 100개인 날은 없다.
- Dynamic(Hit 기준): (수신, 송신, regime) 칸을 test Mean Hit로 최적화했다. 하루 연결 수는 38~45개다.

CI는 10일 블록 bootstrap 10,000회로 구했다. 양수가 앞 모델이 좋다는 뜻이다. refit 배치에서도 순서는 성립했지만 frozen보다 차이가 작다. 전체 결과는 `eval_s0.json`, 마스크는 `masks_*.npz`에 있다.

## 해석

- test에서 순서가 성립한 이유는 자유도의 차이다. Static은 쌍 100개, Dynamic은 칸 300개와 임계값을 test에 맞췄다. 자유도가 큰 쪽이 같은 데이터에서 더 잘 맞는다.
- 같은 구조를 C에 적용하면 순서가 유지되지 않는다. 손실 기준 Dynamic은 C에서 No graph보다 −0.63으로, 오히려 나쁘다.
